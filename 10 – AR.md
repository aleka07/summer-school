# День 10. AR для цифрового двойника

Сегодня я показываю еще один способ смотреть на цифровой двойник.

До этого мы смотрели на данные через OpenEgiz, Grafana и 3D-сцену. Теперь мы открываем AR в браузере: камера видит marker, появляется 3D лампа, а рядом с ней показываются реальные значения из twin.

Главная мысль дня:

```text
цифровой двойник хранит состояние объекта
AR показывает это состояние через камеру
```

То есть AR здесь не отдельная игрушка. Это еще один интерфейс к тому же объекту.

## Что у нас уже лежит в репе

Для этого занятия студентам ничего отдельно скачивать не нужно. Все AR-файлы уже лежат внутри репозитория OpenEgiz:

```text
data-generator/AR/local
```

Там есть:

```text
server.py
lampa (1).html
lampa (1).obj
lampa (1).patt
```

Объясняю это так:

```text
server.py         мини-сервер и proxy к Ditto
lampa (1).html   AR-страница
lampa (1).obj    3D модель лампы
lampa (1).patt   marker для камеры
```

В этом уроке мы используем именно локальный вариант, без сертификатов и без отдельного HTTPS server.

## Архитектура

Данные лампочки идут как обычно:

```text
lightbulb_generator.py
  -> Mosquitto
  -> OpenEgiz / Ditto
  -> summerschool:lightbulb-01
```

AR-страница читает уже готовое состояние:

```text
Browser AR page
  -> local server.py
  -> /api/lightbulb
  -> Ditto API
  -> brightness / power_consumption / voltage / temperature
```

Здесь важно проговорить: браузер не ходит напрямую в Ditto.

Почему:

```text
не надо светить пароль ditto:ditto в frontend
могут быть проблемы с CORS
так проще отделить AR-страницу от внутреннего API OpenEgiz
```

Поэтому `server.py` делает две вещи:

```text
1. отдает AR-страницу, модель и marker
2. отдает /api/lightbulb, а внутри сам читает Ditto
```

## Что должно быть готово

Перед началом OpenEgiz уже должен быть поднят.

Проверяем:

```bash
kubectl get pods
```

И смотрим endpoints:

```bash
make endpoints
```

Для этого урока нам важны:

```text
Ditto:      30525
Mosquitto: 30511
AR local:  5555
```

## Проверяем twin лампочки

AR-демо работает с twin:

```text
summerschool:lightbulb-01
```

Проверяю, что в нем есть features:

```bash
curl -s -u ditto:ditto \
  http://localhost:30525/api/2/things/summerschool:lightbulb-01/features \
  | python3 -m json.tool
```

Нам нужны:

```text
brightness
power_consumption
voltage
temperature
```

Если эти поля есть и значения меняются, значит цифровой двойник живой и AR будет что показывать.

## Запускаем генератор данных

Переходим в папку генератора:

```bash
cd ~/openegiz/data-generator
```

Если окружение еще не создавали:

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

Запускаем генератор:

```bash
nohup python3 -u lightbulb_generator.py \
  --mqtt-host localhost \
  --mqtt-port 30511 \
  > lightbulb_generator.log 2>&1 &
```

Проверяем лог:

```bash
tail -f lightbulb_generator.log
```

И еще раз проверяем Ditto:

```bash
curl -s -u ditto:ditto \
  http://localhost:30525/api/2/things/summerschool:lightbulb-01/features \
  | python3 -m json.tool
```

## Узнаем IP виртуальной машины

Теперь нам нужен IP адрес виртуальной машины, чтобы открыть AR-страницу в браузере.

На VM выполняем:

```bash
hostname -I
```

Команда может вернуть несколько адресов. Обычно берем первый адрес из локальной сети.

Например:

```text
192.168.174.132
```

Тогда адрес нашего AR-приложения будет:

```text
http://192.168.174.132:5555
```

У студентов адрес будет свой.

## Разрешаем камеру для локального HTTP

Здесь есть важный момент.

Браузер обычно не дает доступ к камере для обычного `http://`, потому что камера считается secure feature. Для локального урока мы не поднимаем полноценный HTTPS, а говорим браузеру: этот конкретный локальный адрес считать безопасным.

В Chrome или Brave открываем:

```text
chrome://flags/#unsafely-treat-insecure-origin-as-secure
```

Если в Brave, можно открыть так же, либо:

```text
brave://flags/#unsafely-treat-insecure-origin-as-secure
```

Находим флаг:

```text
Insecure origins treated as secure
```

Включаем его:

```text
Enabled
```

В поле ниже вводим адрес нашего AR-приложения:

```text
http://<VM_IP>:5555
```

Например:

```text
http://192.168.174.132:5555
```

После этого обязательно перезапускаем браузер кнопкой `Relaunch`.

И здесь студентам важно сказать: мы разрешаем не весь интернет, а только один локальный адрес нашей VM.

## Запускаем локальный AR server

Переходим в локальную AR-папку:

```bash
cd ~/openegiz/data-generator/AR/local
```

Запускаем server:

```bash
python3 server.py
```

Он поднимает мини-сервер на порту:

```text
5555
```

В актуальной версии `server.py` он слушает все интерфейсы:

```text
0.0.0.0:5555
```

Поэтому его можно открыть не только внутри VM, но и с основной машины по адресу:

```text
http://<VM_IP>:5555
```

Проверяем API:

```bash
curl http://localhost:5555/api/lightbulb | python3 -m json.tool
```

Если видим `brightness`, `power_consumption`, `voltage`, `temperature`, значит server читает данные из Ditto.

## Открываем AR

В браузере открываем адрес:

```text
http://<VM_IP>:5555
```

Например:

```text
http://192.168.174.132:5555
```

Браузер должен попросить доступ к камере. Разрешаем.

Если камера не спрашивается, почти всегда проблема в одном из двух мест:

```text
адрес не добавлен в Insecure origins treated as secure
браузер не был перезапущен после изменения флага
```

## Показываем marker

Внутри AR-страницы используется marker:

```html
<a-marker type="pattern" url="lampa.patt">
```

Камера должна увидеть marker, который соответствует файлу:

```text
lampa (1).patt
```

Когда marker распознан:

```text
появляется 3D лампа
появляется панель с данными
панель раз в секунду читает /api/lightbulb
```

И здесь я проговариваю главный смысл:

```text
мы смотрим не просто на 3D модель
мы смотрим на модель, связанную с цифровым двойником
```

В Grafana мы видим dashboard. В AR мы видим тот же объект через камеру. Источник состояния один и тот же: OpenEgiz.

## Быстрая диагностика

Если страница не открывается, проверяем, что server запущен:

```bash
ss -ltnp | grep 5555
```

В нормальном варианте там должно быть:

```text
0.0.0.0:5555
```

Если видим только `127.0.0.1:5555`, значит у студента старая версия `server.py`. Тогда нужно подтянуть свежий `openegiz`:

```bash
git pull
```

Если API не работает:

```bash
curl http://localhost:5555/api/lightbulb
```

Если API отвечает ошибкой, проверяем Ditto:

```bash
curl -s -u ditto:ditto \
  http://localhost:30525/api/2/things/summerschool:lightbulb-01/features \
  | python3 -m json.tool
```

Если страница открылась, но камера не работает:

```text
проверить chrome://flags/#unsafely-treat-insecure-origin-as-secure
проверить, что там введен именно http://<VM_IP>:5555
проверить, что флаг Enabled
перезапустить браузер
```

Если камера работает, но лампа не появляется:

```text
marker должен быть хорошо виден
камера должна быть наведена ровно на marker
нужно нормальное освещение
иногда помогает обновить страницу
```

Если данные на панели не обновляются:

```text
сначала проверяем /api/lightbulb
потом проверяем features в Ditto
потом смотрим лог lightbulb_generator.log
```

## Итог дня

Сегодня мы добавили AR как еще один слой поверх цифрового двойника.

Финальная цепочка:

```text
lightbulb_generator.py
  -> Mosquitto
  -> OpenEgiz / Ditto
  -> summerschool:lightbulb-01
  -> local server.py
  -> Browser AR page
```

И это хорошая фраза для закрепления:

```text
данные живут в OpenEgiz
визуализация может быть любой
Grafana, 3D, AR — это разные способы смотреть на один twin
```
